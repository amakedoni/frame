# Пилот независимой разметки

Подготовлены 50 комментариев из YouTube Spam Collection и 50 снимков американской части RDD2022 train. Это проверка codebook на исходных данных, а не новые примеры для обогащения. Каждый участник размечает все 100 заданий самостоятельно.

## Что открыть сначала

1. Прочитать [codebook версии 0.1](../../docs/annotation_codebook.md).
2. Проверить, что рядом существует папка `local/`: в ней `youtube_tasks.json`, `rdd_tasks.json` и `images/` с 50 снимками без рамок. Она не публикуется в Git.
3. Если задач ещё нет, из корня проекта выполнить `python scripts/prepare_annotation_pilot.py`. Нужны исходные архивы и профили первого EDA. Повторный запуск не перезаписывает существующий набор.

Сборка использует seed 42. Для текста взяты по пять примеров каждого исходного класса из каждого из пяти файлов; метки не включены в задания. Снимки выбраны с покрытием всех четырёх классов, с приоритетом редких D40 и D20. Известные точные повторы, совпадения с официальным test и кандидаты на близкие повторы исключены. Это целевая пилотная выборка, а не оценка естественной распространённости классов.

## Запуск Label Studio в Windows

На этом компьютере Label Studio уже установлен, учётные записи A/B и по два проекта созданы, задания импортированы. Вход A — `http://127.0.0.1:8081`, B — `http://localhost:8082`. Разные имена хоста позволяют держать обе сессии в одном браузере без замены cookie входа. Локальные имя входа и пароль находятся соответственно в `.annotation-state/A/access.json` и `.annotation-state/B/access.json`; эти файлы не отправляются в Git.

Из корня репозитория в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_annotation.ps1 -Annotator A -Background
```

При первом запуске на новом компьютере создаётся отдельное окружение и устанавливается Label Studio 1.23.2. Это может занять несколько минут; нужны Python с `venv` и доступ к PyPI. Основное окружение EDA не изменяется. Ключ `-Background` запускает локальный сервер в фоне; повторная команда проверяет занятый порт и не создаёт второй сервер поверх первого.

Участник B запускает ту же команду с `-Annotator B`. На другом компьютере сначала нужно получить те же исходные архивы и собрать пилот тем же скриптом. После установки можно создать свои учётные записи и проекты через интерфейс, либо до первого запуска выполнить `python scripts/setup_annotation_projects.py A --initialize-user`, запустить сервер, затем `python scripts/setup_annotation_projects.py A`. Для B используются те же команды с B. Скрипт запускается Python из окружения Label Studio, например `.annotation-venv/Scripts/python.exe`. Автоматически созданные локальные пароли доступны только в исключённой из Git папке состояния.

У каждого участника своя база Label Studio и два проекта:

| Проект | Конфигурация интерфейса | Файл заданий |
| --- | --- | --- |
| YouTube pilot | `annotation/label_studio/youtube.xml` | `annotation/pilot/local/youtube_tasks.json` |
| RDD pilot | `annotation/label_studio/rdd.xml` | `annotation/pilot/local/rdd_tasks.json` |

На текущем компьютере интерфейсы и хранилище настроены скриптом. При ручном создании проекта открыть Labeling Setup → Code, вставить XML и импортировать соответствующий JSON. Для проекта RDD добавить Settings → Cloud Storage → Add Source Storage → Local Files. Абсолютный путь — папка `annotation/pilot/local/images` внутри этого репозитория. Не запускать автоматическую синхронизацию изображений как отдельных задач: задания уже импортированы из JSON. Локальное хранилище нужно для разрешённого доступа к указанным файлам. Переменная корня файлов задаётся скриптом на `annotation/pilot/local`.

Проверить первое задание: комментарий виден как текст, изображение загружается без рамок, доступны нужные классы и поле времени. Не импортировать файлы из `private_reference/`. Они содержат соответствия исходным записям и доступны только для технической проверки после двух проходов. Раздельные базы исключают показ ответов другого участника в рабочем проекте, но сами по себе не являются защитой от чтения файлов вне него.

## Во время работы

Отмечать фактическое активное время секундомером и записывать в `time_seconds`. Для `accept` у текста должна быть метка, у снимка — рамки всех найденных дефектов. `no_damage` используется только для снимка без целевых повреждений и не содержит рамок. Для `discuss` и `exclude` требуется пояснение. Непосредственно перед Submit проверять заполнение этих полей: конфигурация не проверяет все смысловые сочетания автоматически.

Не обсуждать конкретные задания до завершения обоих проходов. Не смотреть исходные CLASS/XML, приватное соответствие и ответы второго участника. Метки в импортируемых JSON отсутствуют, предсказания моделей не используются.

## Экспорт и сдача

После завершения каждого проекта выбрать Export → JSON и сохранить четыре исходных файла:

```text
annotation/exports/pilot/A_youtube.json
annotation/exports/pilot/B_youtube.json
annotation/exports/pilot/A_rdd.json
annotation/exports/pilot/B_rdd.json
```

Экспорты пока отсутствуют. После их появления проверяются одинаковые `data.item_id`, полнота, время, метки, рамки и согласованность. Первые ответы сохраняются, итоговые решения после обсуждения записываются отдельно. Если правила менялись, сохранить версию codebook и номер прохода.

Справка по инструменту: [рамки](https://labelstud.io/templates/image_bbox), [классификация текста](https://labelstud.io/templates/sentiment_analysis), [локальные файлы](https://labelstud.io/guide/storage_local), [установка](https://labelstud.io/guide/install).
