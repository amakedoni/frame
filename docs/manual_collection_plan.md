# Сбор новых реальных данных

План от 22 октября 2026 года. Выбран смешанный сбор дорожных изображений: собственные фотографии и отбор из открытых источников. Пилот на исходных UCI/RDD2022 не входит в объём нового сбора.

## Объём и критерии

Условия курсовой требуют 50–100 новых экземпляров на класс либо обоснованный пропорциональный объём. Начальная цель — нижняя граница этого диапазона:

| Данные | Цель после отбора и двух разметок | Источник |
| --- | --- | --- |
| `ham` | 50 новых уникальных комментариев | Комментарии к англоязычным музыкальным видео |
| `spam` | 50 новых уникальных комментариев | Те же источники и контекст; поиск рекламных комментариев |
| `D00` | 50 разных снимков с продольной трещиной | Собственная съёмка и подходящие открытые фотографии |
| `D10` | 50 разных снимков с поперечной трещиной | Собственная съёмка и подходящие открытые фотографии |
| `D20` | 50 разных снимков с сеткой трещин | Собственная съёмка и подходящие открытые фотографии |
| `D40` | 50 разных снимков с выбоиной | Собственная съёмка и открытый источник Figshare |

Для изображений это внутренний консервативный план: считаются разные снимки с классом, а не десятки рамок на одном снимке. Один снимок может содержать несколько классов, но остаётся одной записью данных. После разметки отдельно приводятся число уникальных снимков и число рамок каждого класса. Серия кадров одного дефекта получает один `group_id`; близкие кадры не увеличивают число независимых примеров.

Собирать следует с запасом: часть кандидатов окажется повтором, нецелевым примером или неоднозначной записью. Наличие класса до независимой разметки — только предположение для поиска, а не окончательная метка.

## 1. Комментарии

1. Открыть 5–10 англоязычных музыкальных видео и просматривать комментарии в одном выбранном порядке. Записать ID видео, способ сортировки и период просмотра. Не брать только верхние или только явно рекламные комментарии без описания такого отбора.
2. Копировать реальные тексты без переписывания, перевода и дополнения. Сохранять ссылку на комментарий, дату сбора, ID видео и участника, выполнившего отбор. Имя автора не требуется для классификации.
3. Для `ham` и `spam` использовать одинаковый контекст. SMS и отзывы из магазинов автоматически не добавлять.
4. Проверить совпадения с исходными UCI и внутри нового сбора. Основная проверка — SHA-256 текста после удаления крайних пробелов; шаблонные и почти одинаковые сообщения просмотреть отдельно.
5. Зафиксировать условия использования источника и допустимый способ передачи текстов преподавателю. Открытая видимость комментария сама по себе не задаёт лицензию; лицензию UCI нельзя автоматически приписывать новым комментариям.
6. Передать отобранные тексты обоим аннотаторам без предварительных меток.

Ручной просмотр можно дополнить получением кандидатов через [YouTube Data API](https://developers.google.com/youtube/v3/docs/commentThreads/list). Для API потребуется свой ключ; его сохраняют только локально. В журнале отдельно указываются способ получения кандидатов и ручной отбор. API сейчас не запускался, новые комментарии ещё не собраны.

## 2. Собственная съёмка

Снимать реальные дефекты асфальтового дорожного покрытия с ракурсом, позволяющим определить направление дороги и границы повреждений. Сохранять исходный файл; не рисовать трещины, не дорисовывать дефекты и не применять аугментации к разделу ручного сбора.

Для каждой фотографии фиксировать автора, дату, участок дороги и `group_id`. Точное местоположение при необходимости хранить в закрытой части метаданных. Записать разрешённый способ использования собственных снимков. Фотографии общего плана, размытые кадры и снимки, на которых предполагаемый дефект скрыт, отправлять на проверку качества до разметки.

Один видимый дефект достаточно снять один раз для основного набора. Дополнительные ракурсы хранить в той же группе и не разносить между train/validation/test. Оригиналы складывать в `data/manual/local/own_images/`.

## 3. Открытые фотографии

Первый проверенный источник — [Pothole detection using computer vision in challenging conditions](https://figshare.com/articles/figure/Potholes_dataset_with_YOLO_annotations/21214400), версия 3, DOI `10.6084/m9.figshare.21214400.v3`. В метаданных Figshare на 22.10.2026 указана CC BY 4.0. Авторы: Boris Bučko, Eva Lieskovská, Katarína Zábovská, Michal Zábovský. Сохранять название, DOI, авторов, лицензию и сведения об изменениях при использовании материалов.

Этот источник содержит кандидатов на D40. Он не закрывает потребность в трёх классах трещин. Готовые рамки источника в проекты разметки не импортируются.

Для первого отбора подготовлена небольшая очередь фотографий в `data/manual/local/candidates/figshare_21214400_v3/`. Для каждого кандидата в `manifest.json` сохранены архивный путь, авторы, URL, лицензия, время получения, размеры, хеши и результат автоматической проверки против американской части RDD2022. Значение `pending_human_review` означает, что пример ещё не принят.

Первый обзор показывает повторяющиеся виды небольшого участка дороги в разных условиях. Поэтому 12 полученных файлов пока нельзя считать 12 независимыми повреждениями. Всем назначена временная общая группа до ручной проверки мест и конкретных дефектов. Ночные и мокрые кадры дополнительно требуют оценки видимости.

Порядок ручного отбора:

1. Открыть снимок в исходном разрешении. Проверить, что это фотография целевого дорожного покрытия и выбоина различима.
2. Оценить ракурс и масштаб относительно RDD2022. Сильно отличающиеся крупные планы не включать автоматически; отличия источника описать в анализе.
3. Проверить повторы внутри очереди и с базовым RDD. Совпадение пикселей исключает новизну; близкий dHash — повод для просмотра, а не доказательство совпадения. Проверка американской части не доказывает отсутствие пересечений со всеми шестью странами.
4. Записать решение `accept` или `reject`, ФИО/ID отбиравшего участника, дату и причину. Только после этого переносить запись в список принятого ручного сбора.
5. Присвоить новый ID `IMG-M...` и группу источника/участка. Скрыть чужие рамки и передать один и тот же снимок обоим аннотаторам.

Загрузка кандидатов скриптом не считается выполненным ручным сбором. Сведения о готовности обновляются по фактическому отбору людей.

## Запись принятого примера

Шаблон метаданных — [record_template.json](../data/manual/record_template.json). Он содержит пустые поля и не считается собранной записью. Для каждого принятого примера обязательны постоянный ID, тип данных, путь к исходнику, источник, дата обращения, участник, сведения об использовании и группа. Для внешнего снимка указываются авторы и лицензия; для собственного — автор и зафиксированное разрешение.

Принятые записи хранятся в закрытом `data/manual/local/accepted.jsonl`, по одному JSON-объекту в строке. Этот файл появится после первого фактического отбора. Тексты, фотографии и исходные ответы пока не отправляются в публичный Git; скрипты, правила и обезличенные результаты проверок можно хранить в репозитории.
